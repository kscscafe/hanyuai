## 3. 決定事項・ナレッジ

### TTS 設計
- **自動再生 → ボタン再生**：AI 返答ごとに音声が勝手に流れる UX より、ユーザーが聴きたい時だけタップする方が学習用途に合う
- **既存の `SpeechSynthesizer` (AVSpeechSynthesizer) は温存**：HSK1〜3 例文用と、新 `TTSService`（OpenAI TTS）はチャット返答用と、責務を分離
- **ベースURL集約**：`APIConfig.baseURL` で `AIService` と `TTSService` のエンドポイントを統一管理
- **Optional chaining → guard let self パターン**：`Task<()?, Never>` 型推論の罠を回避するため、Task クロージャ内で `guard let self else { return }` を使う

### キャラクター情報の集約
- `ChatCharacter` に集約すべきプロパティ：`displayName` / `nameJP` / `profile` / `avatarImageName` / `hometownLabel` / `systemPrompt` / `openingMessage`
- View 側で同じ情報をハードコードしないルールを今回確立（`origin` を `OnboardingCharacterView` から `ChatCharacter` に移管）

### App Store Offer Codes と自前プロモコードの整理
- **Offer Codes は IAP 紐付き専用**：割引・無料期間しか配れず、ターン直配布（HANYU10 / REI50 など）には**使えない**
- **自前プロモが審査セーフな範囲**：「自分で買ったユーザーをよりお得にする方向」「マーケティング目的の無料配布」「お詫び付与」「オンボーディング強化」は OK
- **アウト**：コードを有償販売、物販紐付け、外部決済とのブリッジ（Apple 経由を回避した価値配布）

### バージョン番号の方針
- App Store Connect は同じ短いバージョン内で `CFBundleVersion` の単調増加が必須。違うバージョン間ではリセット可能だが、**履歴の連続性を保つため Build 9 → 10 を採用**

### GitHub タグ位置の判断
- App Store にバイナリで上げた状態を最も正確に表すコミットを選ぶ。docs のみのコミット（`6b53d7e`）は本体コードに影響なくても、**タグ位置はリリース後の文書を含まないコミット（`7a72cee`）にするのが履歴上の意味的に正しい**

## 4. 発見した課題

### REI50 アプリ側入口の不在
- v1.0 / v1.1 / v1.2 すべてで `ChatView` のプロモコード入口（"コードを入力" ボタン・promoCodeBanner・PromoCodeView シート）が**コメントアウト**されている
- コメントには「App Store Offer Codes 移行予定」とあるが、Offer Codes ではターン直配布できないため**完全な置き換えにはならない**
- v1.2.0 はすでに審査提出済みのため REI50 は v1.2 では使えない。v1.3 以降で別アプローチ（UI 復活・ディープリンク等）が必要

### v1.2.0 の iOS 側ソース未コミット
- TTS / プロフィールモーダル / `pbxproj` のバージョン bump など、**App Store にアップロードしたバイナリのソースが working tree に残ったまま**
- 履歴の正しさのため、審査結果が出る前後で v1.2.0 タグ位置となるコミットを作る必要がある

### Xcode 新規ファイル登録の手作業
- セッション中の SourceKit 診断（`Cannot find type 'ChatCharacter' in scope` 等）は、新規 Swift ファイルが pbxproj 未登録のときに macOS コンテキストで誤検知される
- `APIConfig.swift` / `TTSService.swift` / `CharacterProfileView.swift` は Xcode 側で hanyuai ターゲットに追加済み（杉崎側でビルド成功確認済み）
